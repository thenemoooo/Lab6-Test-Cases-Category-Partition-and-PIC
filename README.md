## A2. Хязгаарлалтууд ба "N → M"

| Утга | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| from=Frozen | [ERROR] | ERROR_FROZEN буцна; алдаа нь бусад шалгалтыг нууна тул нэг удаа шалгана |
| from=Missing | [ERROR] | ERROR_NO_FROM; цаашдын бүх шалгалтыг нууна |
| to=Missing | [ERROR] | ERROR_NO_TO |
| to=SameAsFrom | [ERROR] | ERROR_SAME_ACCOUNT |
| amount=Zero | [ERROR] | ERROR_BAD_AMOUNT (amount ≤ 0) |
| amount=Negative | [ERROR] | ERROR_BAD_AMOUNT (amount ≤ 0) |
| amount=OverBalance | [ERROR] | ERROR_INSUFFICIENT |
| amount=OverLimit | [ERROR] | ERROR_LIMIT |
| amount=ExactBalance | [SINGLE] | Хязгаарын утга; амжилттай (201) болохыг нэг удаа шалгахад хангалттай, бусад параметртэй хослуулах шаардлагагүй |
| to=SameAsFrom | [IF from≠Missing] | "from-той ижил" гэдэг утга нь from байгаа үед л утгатай |
| amount≠Normal | [IF from≠Missing] | from байхгүй бол үлдэгдэл, лимит тодорхойгүй тул дүнгийн шалгалт утгагүй |

**Давуу эрэмб (олон алдаа зэрэг гарвал):** from → to → amount, өөрөөр хэлбэл
`NO_FROM → FROZEN → NO_TO → SAME_ACCOUNT → BAD_AMOUNT → INSUFFICIENT → LIMIT`.
**Үндэслэл:** Эхлээд хүсэлтийн оролцогч дансуудыг (from, to) шалгаж, дараа нь л дүнгийн бизнес дүрмийг (amount) шалгана, учир нь данс байхгүй бол
үлдэгдэл, лимитийг бодох боломжгүй; дүнгийн дотор оролтын хэлбэрийг (≤ 0) эхэлж, дараа нь үлдэгдэл, хамгийн сүүлд өдрийн лимитийг шалгана. Энэ нь
тодорхойлолтод алдаануудыг жагсаасан дарааллтай мөн нийцнэ.

**Тооцоо:** бүрэн олонлог = 3 (from) × 3 (to) × 6 (amount) × 2 (currency) = **108**.
Хязгаарлалтын дараа: бүгд хүчинтэй утгын хослол 1 × 1 × 1 × 2 = 2, [SINGLE] 1, [ERROR] 2 + 2 + 4 = 8 → 2 + 1 + 8 = 11, өөрөөр хэлбэл **108 → 11**.

## B3. Дүгнэлт

Гараар хийсэн category-partition нь алдааны семантикийг сайн барьдаг: аль утга [ERROR], аль нь [SINGLE] болохыг, олон алдаа зэрэг гарвал аль нь давуу байхыг өөрөө шийдэж, хүлээгдэх үр дүнг (oracle) тодорхойлдог.
Харин PICT нь утгуудын хос бүрийн хамралтыг математикийн хувьд баталгаажуулдаг бөгөөд мөр үүсгэхдээ хүний анхаарлаас алдах хослолыг гаргаж өгдөг.
Гэвч PICT нь алдаа гэж юу болохыг мэддэггүй тул хязгаарлалтгүй бол нэг мөрөнд хэд хэдэн алдаа хольж, эхний алдаа бусдыг нуух (error masking) асуудал үүснэ.
`~` сөрөг утгын тэмдэглэгээ нь category-partition-ий [ERROR]-той дүйх бөгөөд нэг мөрөнд ≤ 1 алдаа оруулдаг тул тестийн зорилго тодорхой болж, A2-ын IF хязгаарлалт хэрэггүй болсон.
Хоёр аргын гол ялгаа нь гараар хийсэн хүснэгт цөөн (11–15 мөр) боловч алдааны анги бүрийг зориуд сонгодог, харин PICT-ийн гаралт хослолын хамралтыг системтэй өгдөг боловч утга нь зөв сонгогдсоноос хамаарна.
Хамгийн их бодол шаардсан алхам нь олон алдааны давуу эрэмбийг тогтоох явдал байсан, учир нь тодорхойлолт үүнийг зориуд хоосон орхисон тул үндэслэлтэй шийдвэр гаргах хэрэгтэй болсон.
Хоёр дахь хүнд алхам нь Хэсэг A-ийн утгуудыг PICT модель болгож хөрвүүлэх, ялангуяа боломжгүй хослолыг хязгаарлалтаар хасах явдал байв.
Нөгөө талаас PICT-ийн мөр бүрийн oracle-ийг өөрөө давуу эрэмбээс гаргах хэрэгтэй тул хэрэгсэл нь тест дизайныг бүрэн орлохгүй, зөвхөн хослолыг үүсгэх ажлыг хөнгөвчилдөг.
Практикт хамгийн зөв арга нь хоёуланг хослуулах: гараар алдааны анги, SINGLE, давхар нөхцөлийг тодорхойлж, PICT-ээр хэвийн утгуудын хослолыг тоон хувьд хамруулах.
